## 12:29 — Classifier Evasion: Small Input Changes and Large Model Errors - Governance Gaps: Data Loss and Privacy Risks ([↗](https://www.youtube.com/watch?v=lAamZIOUljg&t=749s))

Evasion targets a classifier's decision. The attacker changes input features so that a harmful item is labeled as benign while the underlying risk remains. The method depends on the model and the data type. There is no universal pixel trick for every security product. For an image classifier, subtle changes in an image can sometimes alter the predicted label without being obvious to a person. That illustrates an adversarial example. A defensive team test robustness under realistic variations rather than assuming a clean test score covers hostile inputs. For a malware or alert classifier, an attacker may alter the features or telemetry the model uses. If it misclassifies malicious activity as harmless, a detection can be missed.

Keep independent checks and analyst review in the loop. Never make one model the sole source of truth. Suppose Harbor View's alert classifier usually recognizes a suspicious pattern. An attacker changes part of the input so the classifier now calls it normal, even though the underlying activity is still risky. That is evasion. The attacker did not necessarily change the training set as in poisoning. They change what the deployed model sees now.
