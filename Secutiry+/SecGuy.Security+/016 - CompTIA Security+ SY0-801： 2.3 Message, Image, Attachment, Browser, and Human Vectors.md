Welcome back to the lab. I am SecGuy. In our last module, we analyzed who the threat actors are and what motivates them. Today, we must understand how they reach us. We are covering the first half of objective 2.3 for your Security+ certification. Threat vectors and attack surfaces. Your job on day one is not just to design a defense, but to recognize exactly how an attack enters a system. A threat vector is the specific path an attacker uses to gain access. An attack surface is the total number of exposed entry points that an attacker can use. If you can identify the vector, you are one step away from identifying the correct mitigation.

Let us begin with message-based vectors. These are attacks delivered through communication systems that users already trust. This includes email, short message service, rich communication services, instant messaging, and internal collaboration tools. If an attacker drops a malicious link into a corporate Slack channel or sends an SMS text pretending to be IT support, the message itself is the delivery mechanism. Next, we have image-based vectors. Attackers embed malicious payloads or redirect instructions inside visual elements. You will see attacks utilizing quick response codes, embedded content, and weaponized captions. When a user scans a malicious QR code taped to a parking meter, a technique known as quishing, their mobile device is instantly directed to a credential harvesting portal.

Moving beyond simple text and images, we face attachment-based vectors. These involve malicious payloads

Here is the crucial distinction for the exam and the job. If the malicious action occurs when the user opens or executes the file itself, it is an attachment-based or file-based vector. If the user merely clicks a link inside the body of an email, that remains a message-based vector. Attackers also target the tools users rely on to access the web through browser-based vectors. These vectors exploit vulnerabilities or malicious configurations directly within the web browser architecture. The primary culprits you must monitor are malicious browser extensions and weaponized JavaScript. A user might install a seemingly harmless browser extension to block advertisements, only to have that extension quietly execute malicious JavaScript to scrape session tokens and keystrokes in the background.

In the MGM Resorts breach, attackers found an employee's name on LinkedIn, called the IT help desk, and impersonated them using a believable pretext about a lost password. Human vectors also extend to physical environments. You must account for rogue contractors, unauthorized visitors, and bypass biometric controls. Consider tailgating. A researcher breached a high-security facility by simply carrying two large boxes of pizza and coffee. A polite employee held the door open allowing the attacker to bypass biometric scanners completely. Finally, we have the watering hole attack.
