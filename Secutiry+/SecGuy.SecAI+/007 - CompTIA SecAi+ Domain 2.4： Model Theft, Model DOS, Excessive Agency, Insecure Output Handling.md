LLM06 is sensitive information disclosure. The risk here is simple. Llms are trained on massive data sets. Sometimes that data includes PII, API keys or proprietary code. If a user asks what is the AWS key for the production server and the model was trained on internal Slack logs, it might just tell them the fix data sanitization. You must scrub PII before training. LLM02 is insecure output handling. This is when the AI becomes the attacker. Imagine an attacker sends an email with a hidden JavaScript payload. The AI reads it and summarizes it. If your admin dashboard renders that summary without checking it, that script executes in your admin's browser. This is cross-sight scripting laundered through a chatbot.

The fix? Never trust AI output. Treat it like user input and sanitize it before rendering. This is where AI moves from chatbot to agent. LLM08 is excessive agency. This happens when we give an AI permission to do things like send emails, update databases, or buy products. The risk is obvious. If the AI hallucinates or gets confused, it might delete a database or email your entire contact list.

It has too much power with too few guard rails. LLM07 is insecure plug-in design. This is how the AI takes action. It uses plugins to connect to the outside world. If a plug-in accepts unvalidated input, like a SQL command generated by the AI, you effectively have SQL injection powered by a robot. The fix for both is lease privilege. Don't give the AI admin access and always require a human in the loop to approve high impact actions. Finally, let's talk about the system pair. LLM04 is model denial of service. AI is expensive. Attackers use sponge attacks asking complex questions that are short to write but hard to answer to exhaust your GPU memory.

They aren't stealing data. They are burning your budget and crashing your server. LLM09 is over reliance. This is a human vulnerability. We trust the AI too much. Hackers exploit this with package hallucination. The AI invents a software library that doesn't exist. A hacker creates a real malware package with that name and waits for developers to copy paste the install command. The fix? Verify everything. Code generated by AI is guilty until proven innocent.
