When you type a prompt into chat GPT, the very first thing the model does is chop your sentence into little pieces called tokens. A token isn't always a word. It can be part of a word, a character, or a common phrase. A good rule of thumb for the exam is that 1,000 tokens is about 750 words. Why does this matter for security? Because every model has a limit. We call that a context window overflow and it starts right here with the token. Once we have tokens, we have to give them meaning. This is where the magic happens. This is embeddings. Imagine a massive 3D map. And embedding is simply taking a word and turning it into a list of numbers, a vector that places it somewhere on this map. But here's the cool part. Words with similar meanings are placed closer together. The vector for dog will be mathematically very close to the vector for puppy, but very far away from toaster. The AI doesn't know what a dog is, but it knows that dog and puppy share a similar coordinate in this highdimensional space.

This allows the AI to do math with language. The classic example you'll see in textbooks is this. If you take the vector for king, subtract the vector for man, and add the vector for woman, the math lands you directly on the vector for queen. That is how an LLM understands relationships. It's not reading, it's calculating distance. So, we have these billions of vectors. Where do we store them? You can't put these in a standard SQL database. Standard databases look for exact keyword matches. If you search for car, SQL won't find automobile. It's too rigid. Enter the vector database. This is a specialized database designed to store and search these highdimensional vectors.

Instead of searching for key words, it searches for meaning. This is called semantic search. If I query a vector DB for how to fix a breach, it looks for vectors close to that concept. It might return a document titled incident response guide. Even if the word breach never appears in the title, this technology is the backbone of R A retrieval augmented generation which allows companies to feed their private data into public AI models safely. Finally, we have to talk about the context window. This is the short-term memory of the model. It includes everything currently in the conversation, your system instructions, the documents you uploaded, and the user's current prompt. Now this is where prompt engineering comes in and you need to know this for the exam.

You have two main ways to use this window. First, there is zero shot prompting. This is where you ask the AI a question with no examples. It's risky because the AI has to guess the format you want. Second, there is fewot prompting. This is where you provide examples inside the context window to guide the model. From a security perspective, fshot is safer because you are constraining the model's behavior with clear examples before it generates an answer. Every model has a hard limit on this window. For GPT4, it's massive. For smaller open-source models, it might be tiny. In a security context, the context window is a prime target. If an attacker can fill this window with garbage data, the model might forget the safety rules hidden at the start of the conversation.
